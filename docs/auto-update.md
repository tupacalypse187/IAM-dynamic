# 🔄 Auto-Update & Releases

Desktop updates use `electron-updater` with a static file feed (S3 + `latest.yml`). The policy is strict: **download in the background, install only when the user restarts** — nothing ever applies silently.

## 🧠 How It Works

1. Main checks the feed on launch and every 4 hours (`desktop/src/main/updater.ts`).
2. When a newer version appears, it downloads automatically and notifies the renderer over IPC.
3. The renderer shows a toast ("Update 1.1.0 found — downloading") and, once ready, a persistent **Restart & apply** banner (`frontend/src/components/update-manager.tsx`).
4. `Help → Updates` shows the current version and a manual **Check for updates now** button.
5. Updates are disabled entirely when `IAM_DESKTOP_UPDATE_FEED_URL` is unset (local dev, unpacked builds).

Every lease, generation, and revocation lives in the local SQLite ledger, which survives updates untouched.

## 🗂️ Feed Layout

Any static host works (S3 + CloudFront recommended). Per platform channel:

```text
s3://<bucket>/desktop/
├── IAM Dynamic-1.1.0-arm64-mac.zip
├── latest-mac.yml            # macOS channel descriptor (electron-updater reads this)
├── IAM-Dynamic-Setup-1.1.0-x64.exe
├── latest.yml                # Windows channel descriptor
└── *.blockmap                # differential-download metadata
```

`latest{,-mac}.yml` files are generated by `electron-builder -p always` — never hand-edit them.

## 🚀 Releasing

```bash
# 1. macOS (local, signed + notarized when creds are set)
cd desktop
IAM_DESKTOP_UPDATE_FEED_URL=https://releases.example.com/desktop \
  npx electron-builder --mac --arm64 -p always \
    -c.publish.provider=generic \
    -c.publish.url="$IAM_DESKTOP_UPDATE_FEED_URL"
# Upload release/*.zip + release/latest-mac.yml to the feed.

# 2. Windows (CodeBuild, on-demand — never per-push)
aws codebuild start-build --project-name iam-dynamic-desktop-windows
# Artifacts (exe + latest.yml) land in s3://<bucket>/desktop/ automatically.

# 3. Linux
npm run dist:linux   # AppImage + deb (Docker for glibc parity)
```

Bump `desktop/package.json` `version` before building — `electron-updater` compares semver, and equal versions are ignored.

## 🏗️ Windows Builds on CodeBuild

No Windows host needed. The project is **manual/tag-triggered only** to keep minutes and cost down.

**One-time setup** (creates the project, starts nothing):

```bash
BUCKET=my-release-bucket \
ROLE_ARN=arn:aws:iam::123456789012:role/CodeBuildWindows \
FEED_URL=https://releases.example.com/desktop \
  ./desktop/scripts/setup-codebuild.sh
```

| Requirement | Details |
| ----------- | ------- |
| Image / env | `WINDOWS_SERVER_2022_CONTAINER`, `aws/codebuild/windows-base:2022-1.0` |
| Spec | [`desktop/buildspec-windows.yml`](../desktop/buildspec-windows.yml) — Node 22, `npm ci`, frontend build, icons (best-effort), `electron-builder --win -p always` with the generic provider pointed at `$UPDATE_FEED_URL` |
| Cache | `node_modules`, Electron + builder caches on S3 (keeps rebuilds to minutes) |
| Artifacts | `release/*.exe`, `release/latest.yml`, `*.blockmap` → `s3://<bucket>/desktop/` |
| IAM role | Trusts `codebuild.amazonaws.com`; read/write the bucket + CloudWatch Logs |

Rehearse the CodeBuild run **mid-project**, never on release day — the first Windows build is where missing native prebuilds and cache misses show up.

## 🧪 Testing an Update End-to-End

1. Build and install version `N` locally (or from the feed).
2. Bump to `N+1`, build with `-p always`, upload the new artifacts + `latest*.yml` to a **staging** feed prefix.
3. Point the installed app at the staging feed, restart, and confirm: toast → download → **Restart & apply** banner → relaunch on `N+1` with the ledger intact.

## 🔮 Future Hardening

| Item | Trigger |
| ---- | ------- |
| Azure Trusted Signing + signed NSIS | Before any broad Windows rollout (kills SmartScreen friction) |
| `Developer ID Installer` cert + `.pkg` | Before MDM/fleet deployment on macOS |
| MSIX | After signing exists (unsigned MSIX is worse than NSIS — requires sideload trust on every machine) |
| Staged rollouts / channels (`latest-beta.yml`) | When the user base outgrows "everyone gets it at once" |

## 🛠️ Troubleshooting

| Symptom | Cause / Fix |
| ------- | ----------- |
| "Update check failed" toast | Feed URL unreachable or `latest*.yml` missing — the error message names the URL; app keeps working. |
| New version never offered | `version` in `desktop/package.json` wasn't bumped, or the wrong `latest*.yml` was uploaded. |
| SmartScreen on Windows install | Expected while NSIS is unsigned; click through (or wait for Azure signing). |
| Update downloads every launch | Feed serves a `latest*.yml` whose version ≤ installed — re-upload after a real version bump. |
